# Coherent source-runtime profile

This is implementation infrastructure, not a completed or validated SDK release.
No behavioral CPU tests or GPU tests were executed for this checkpoint. The
source SDK, patched Rust standard library, LLVM, Mesa and WebGPU artifacts still
have to be compiled together and validated after implementation is complete.

## Two explicit profiles

The default `COSMO_RUNTIME_PROFILE=stock-sdk` retains the existing Cosmocc 4.0.2
bootstrap and upstream Rust adapters. `source-built` selects a whole SDK produced
from committed Cosmopolitan source. Never copy source headers or runtime objects
into a stock SDK, or combine a source runtime with stock Rust adapters.

`source_runtime.py` clones clean committed source into a fresh temporary build,
copies a checksum-verified bootstrap compiler, and invokes the complete
`tool/cosmocc/package.sh` recipe. It packages both x86-64 and AArch64, all runtime
modes, compiler drivers, headers, CRT, libc, libc++, linker scripts and loaders.
Compiler archive download/checksum/extraction failures abort packaging. The
bootstrap compiler remains an input, not the packaged runtime.

After the implementation gate, a compile-only production invocation is:

```sh
python3 toolchain/source_runtime.py build \
  --source "$PWD" --bootstrap-sdk /absolute/verified-stock-sdk \
  --output /absolute/new-source-sdk --jobs 1
python3 toolchain/source_runtime.py verify --sdk /absolute/new-source-sdk
```

The bootstrap must have the metadata generated by `toolchain/bootstrap.py`, not
just a directory named after a release. Output must not exist. Source must be
committed and clean, with no submodules or reused object files. The full package
build is expensive. It runs build tools but does not run application probes.

## Identity and compatibility

`SOURCE_RUNTIME.json` records source repository/commit/tree, reviewed ABI input
hashes, bootstrap identity, package recipe, and an exhaustive file/mode/symlink
inventory. `runtime_identity` is a canonical SHA256 of this record. Verification
rejects missing, extra, changed or escaping files and incomplete runtime layouts.
Internal relative symlinks are retained, not replaced with their target text.

This is content identity, not a signed attestation or proof of runtime behavior.
Host tools are not hermetically pinned. The Rust adapter profile pins selected
ABI source fingerprints and its adaptation patch; those checks cannot prove all
cross-platform ABI behavior. Source edits affecting the boundary require review,
a new profile/pin, and eventual compile and behavioral validation.

## Rust profile

`third_party/rust_ape/source-runtime.json` pins adaptations imported from
`fix/rust-ape-source-runtime` at `3b155638ddd4f69471785d8050dca370b9e077ec`.
The original stock upstream snapshot stays intact. A source-only overlay updates
the descriptor/process/path interfaces and removes superseded overrides.

```sh
export COSMO_RUNTIME_PROFILE=source-built
export COSMO_RUNTIME_SDK=/absolute/new-source-sdk
export COSMO_RUST_BUILD_ROOT="$PWD/o/rust-source"
bash third_party/rust_ape/run.sh setup
```

Choose a fresh build root when changing profiles or runtime identities. Setup
installs the complete verified source SDK, regenerates shim ABI tables from its
headers, and binds their hashes. Reuse checks the exact adapter source set and
linker wrapper, SDK identity and generated tables. The source-only linker rebuilds
every shim object on each link rather than trusting mtime-only caches. Export
requires the exact object set derived from verified source filenames, with no
missing, extra or colliding objects. SDK lockfiles remain mutable.
Once bound, upstream stock setup is not invoked again, so a missing stock
bootstrap stamp cannot replace the source runtime. Missing generated setup files
require a fresh root. `setup`/`gen-shim` can repair incomplete table generation.
Ordinary installation errors roll back the SDK swap; abrupt process/host death
can leave an incomplete root, which is rejected rather than silently adopted.

## LLVM, Mesa and WebGPU

LLVM and Mesa `LINK.json` and WebGPU `BUILD.json` carry a `runtime` record. Source
records contain `kind=source-built-cosmopolitan-runtime`, `source`,
`runtime_identity` and `runtime_abi`. Legacy stock records use `kind=stock-sdk`.
The source identity is included in build-cache keys and checked at consumption
and publication. LLVM records every dependency archive hash; Mesa records its
complete registration/Mesa/LLVM link archive closure. Consumers verify these
hashes and ordinary archive structure, and SDK staging verifies copied bytes. A source-built manifest cannot be treated as a stock SDK.

LLVM and Mesa support `--no-run`. WebGPU supports `--compile-only`, skipping
native ABI/loader execution and forwarding `--no-run` to software-driver builds.
These options compile/link probes without running them. Host compiler utilities,
code generators and `llvm-config` still run as part of building.

WebGPU currently requires its default `o/rust-ape` build root. Use a fresh checkout
for source-mode WebGPU if that root already contains stock output. Set the same
source-profile environment and invoke:

```sh
bash third_party/wgpu_native/build.sh --software --compile-only
```

No recipe is changed to launch GPU workflows or paid infrastructure. Behavioral
CPU validation remains a separate later gate, followed by any GPU validation.

## EasyDifussion-CPP handoff

Do not update its dependency pin to this checkpoint alone. A final handoff needs
the complete selected source SDK and Rust/WebGPU/Mesa/LLVM archive closure built
against it. The consumer's strict handoff schema records `SOURCE_RUNTIME.json`
as a provenance artifact; its exported closure materializes referenced SDK
symlinks into regular files and computes its own identity over selected artifacts.
A matching content identity is necessary, not evidence of successful inference,
Windows execution, GPU behavior, or completion of the wider roadmap.
